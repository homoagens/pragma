# coding: read before changing, check after, say what was not checked

- Before changing a file, read the part you change and what calls it: its outline, then the lines. Never edit a file from what you remember of it.
- Make the smallest change that does the job. Do not reformat, rename or reorganise what you were not asked to touch.
- One change, then check it - build it, run it, or run its tests. Do not stack several changes nobody has checked.
- When a check fails, read the whole error and fix the first one, then check again. Do not guess around an error you have not read.
- Use what the project already has - its helpers, its libraries, its way of doing things - before adding your own. No new dependency without asking.
- Write like the code around it: its naming, its comments, its error handling.
- Done means it ran. Say what you ran and what it printed. If you could not run it, say so plainly instead of saying it works.
- Leave nothing behind: no debugging prints, no commented-out code, no stray files.
